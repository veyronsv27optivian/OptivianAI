🧠 Agent Architecture Overview

Each feature is handled by a professional specialized agent. The Chief Manager Agent coordinates all agents and presents a unified experience to the user. The system uses Gemini API (primary) with DeepSeek and Qwen as fallback providers via OpenRouter. Agents communicate through structured prompts and the execution engine for action delivery.

Autonomous AI Manager (Phase D4.9)

Autonomous AI Manager Ready

A self-operating AI manager singleton with 5 subsystems: Monitor (health checks, task monitoring, anomaly detection), Executor (auto-executes approved actions), Learner (tracks outcomes, adjusts confidence), Reporter (daily/weekly summaries), Scheduler (timed recurring tasks). Features self-healing capabilities and proactive recommendation generation.

AutonomousMonitoringSelf-HealingPhase D4.9
Capabilities: Scheduled health checks every 60s, task health every 5 min, anomaly detection with configurable sensitivity, auto-execution of low-safety actions, proactive recommendations, auto-escalation of critical issues, one-click rollback (30-second undo window), pending action queue with approval UI.
Default registered actions: create_task, update_task, delete_task, send_message, create_notification, save_analysis, get_analyses, create_conversation, update_assignee_status, generate_report, suggest_provisioning, cleanup_data

🏗️ Execution Pipeline Flow

AI generates response → parseIntent() extracts actionable intents (JSON blocks, inline markers, bracketed markers)
→ validateIntent() checks against action registry
→ checkPermission() verifies user has RBAC permission + AI-specific rules
→ Low safety actions auto-execute; high/critical require user approval
→ executeAction() runs handler with rollback support
→ Results logged with [Undo] available for 30 seconds
